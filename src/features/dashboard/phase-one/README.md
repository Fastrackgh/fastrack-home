## Explicitly deferred

No assignment/e-learning portal, behaviour/discipline tracker, or lesson-planning/syllabus-submission workflow was added. The old Teacher “Lesson resources” entry is removed from navigation so the earlier preview does not imply those future items are part of phase one. Existing source components may remain dormant.

## Integration boundary

- `domain.ts`: typed student, bill, payment, expense, plan, event, meal, enquiry, archive, staff, timetable and assessment records; deterministic calculations. Foreign keys use sample IDs today. `termId` resolves to academic year/term. Role names `ACADEMIC_HEAD` and `SECRETARY` need backend support/mapping.
- `usePhaseState.ts`: local store scoped by role + term + selected child; changes survive section navigation but reset on scope changes/reload. Replace its loading and updates with authenticated domain services. It is not an authentication/session provider.
- `Workspace.tsx`: role-gated routing for phase-one panels. Existing `model.ts` controls navigation. All live APIs must independently enforce tenant, permission, class and child ownership.
- `Shared.tsx`: accessible labelled form fields; validation; async save/loading/failure handling; report search/export; print preview. New services can return promises without replacing the form shell. Domain mutation handlers currently update local state only.
- `Finance`, `Enrollment`, `SchoolLife`, `Academics`: feature screens. They consume typed records and the store; do not send display strings as backend money/mark values.
- `AdmissionPortal`: same-origin, memory-only cross-tab demo; replace broadcast with a validated public application endpoint and staff queue. An open staff preview is required to receive a sample application; nothing is durably queued.

Before integration: confirm actual academic dates, grading and GPA policy, receipt format/numbering (the PDF says “100s” but gives `001, 002, 003`), concession stacking, assigned-class scope and secretary permissions. Current preview uses the explicit three-digit examples. Move receipt generation, reminders, penalties, aggregate totals and authorization to the server. Persist uploaded files through an authorized service, and implement notification dispatch separately from saved drafts.

## Validation

`pnpm test:dashboard` covers tuition/scholarship bases, fee-only settlement, separate receipt sequences, overlapping calendar closures, payment-plan cancellation, date/weekday scheduling conflicts, weighted grades, child/class scoping and role menus/deferred exclusions. `pnpm exec tsc --noEmit` checks the frontend contracts. Production build checked with `pnpm build`.

Browser visual/click-through QA remains unverified: computer-use reported no available browsers/apps and a native pipe startup failure. Suggested manual review: choose each role; open each sub-menu; post a sample partial/final payment; print both receipt types; create/cancel a calendar closure; upload/read a document; submit an admission while a staff tab is open; enroll that enquiry; reject a timetable conflict; change grading weights and regenerate a report; repeat at mobile width.
